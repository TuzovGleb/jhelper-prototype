# Прототип нового лендинга jhelper.ru

Статический HTML/CSS-прототип пересборки сайта по `План_пересборки_сайта_jhelper.md`.
Дизайн-система снята один-в-один с боевого сайта — новых цветов, шрифтов и радиусов не вводилось.

**Назначение:** согласовать структуру и тексты визуально, затем отдать разработчику как эталон вёрстки для переноса в Next.js.

## Как открыть

**Онлайн:** https://tuzovgleb.github.io/jhelper-prototype/

**Локально** — из корня `Code/jhelper`:

```bash
python -m http.server 8010 --bind 127.0.0.1 --directory prototype
```

Дальше — `http://localhost:8010`. Конфигурация уже добавлена в `.claude/launch.json` под именем `jhelper-prototype`.

### Про ссылки

Ссылки внутри сайта — относительные (`tarify/`, `../oferta/`, `../assets/…`). Так страницы работают и на GitHub Pages под подпутём `/jhelper-prototype/`, и на домене-корне.

**При переносе на jhelper.ru URL получаются ровно те, что нужны:** `/tarify`, `/oferta`, `/privacy`, `/rekvizity` — те самые адреса, которые проверяет мониторинг платёжного сервиса. Относительные ссылки на домене-корне резолвятся в них один в один, менять ничего не надо.

## Два важных момента, всплывших при сборке

### 1. Спорные пункты безопасности уже утверждены в самих документах

Два пункта блока «Безопасность» лежат в `index.html` **закомментированными** — «данные хранятся и обрабатываются в России» и «ваши документы не используются для обучения моделей». Но оказалось, что оба уже прямо заявлены в юр-документах:

- **Политика конфиденциальности, п. 5.5:** обработка ПДн граждан РФ ведётся с использованием баз данных, находящихся на территории Российской Федерации.
- **Оферта, п. 10.3:** материалы Пользователя не используются для обучения моделей ИИ без отдельного явного согласия.

То есть вопрос не в том, можно ли это писать на лендинге, а в том, **соответствует ли этим двум пунктам фактическое положение дел** — где физически стоят серверы и что написано в договоре с LLM-провайдером. Если реальность расходится с документами, проблема серьёзнее лендинга: расхождение уже опубликовано в оферте и политике. Проверить нужно в любом случае.

### 2. Роут тарифов: `/tariffs` vs `/tarify`

Источники расходятся:

- `oferta.md` (термин «Тарифы») ссылается на `https://jhelper.ru/tariffs`;
- `checklist-i-soglasie.md` §2 требует `/tariffs`, `/oferta`, `/privacy`, `/requisites`;
- `План_пересборки_сайта_jhelper.md` §3 задаёт `/tarify`, `/oferta`, `/privacy`, `/rekvizity`.

В прототипе взяты роуты из плана пересборки (`/tarify`, `/rekvizity`), и ссылка в тексте оферты приведена к ним. **Перед публикацией зафиксировать один вариант** и синхронно поправить текст оферты в `Юр_документы/oferta.md` — иначе ссылка внутри договора будет вести на 404.

### 3. Ставка НДС: в .docx осталось 20%, в .md уже 22%

В `Юр_документы/` лежат две версии каждого документа, и они разошлись:

- `tarify.md` (11 августа) — «в том числе **НДС 22%**»;
- `Тарифы.docx` (7 августа) — «в том числе **НДС 20%**».

В прототипе взято **22%** — это действующая ставка с 01.01.2026 (ФЗ № 425-ФЗ от 28.11.2025). `.docx` — более ранний экспорт, его надо перевыгрузить из `.md`, иначе у юриста и у эквайера окажутся разные цифры.

В оферте расхождения нет: там нейтральное «с учётом НДС по действующей ставке» в обеих версиях.

### 4. Приложенные .docx новых данных не содержат

Все четыре `.docx` — это Word-экспорт тех же `.md`, снятый раньше. Незаполненные места в них те же самые: в оферте 8 плейсхолдеров, в политике 8, в реквизитах 4, в тарифах 4 — e-mail, даты редакций, сроки, раздел ЛК, ответственный за ПДн. Брать оттуда нечего; единственное отличие — устаревшая ставка НДС (см. выше).

Источником правды для прототипа остаются `.md`-файлы.

2. **SSR/SSG обязателен** для лендинга и четырёх юр-страниц. Сейчас лендинг рендерится только на клиенте — при отключённом JS видно «Загрузка…». Это бьёт и по SEO, и по мониторингу платёжного сервиса: страницы должны открываться **без авторизации и без JS**.
3. **Все четыре юр-страницы — публичные.** Сайт закрыт регистрацией, но `/tarify`, `/oferta`, `/privacy`, `/rekvizity` должны открываться анонимному посетителю.
4. **Чекбокс согласия при регистрации** — не проставлен по умолчанию, со ссылками на `/oferta` и `/privacy`. Текст — в `checklist-i-soglasie.md` §3.
5. **Экран оплаты**: до нажатия кнопки видны наименование юрлица, ИНН, стоимость, периодичность списания при автопродлении и способ его отмены. Шаблон текста — в `checklist-i-soglasie.md` §4.
6. **Логотипы платёжных систем** в футере сейчас текстовые чипы — заменить на изображения по требованиям эквайера.
7. Мобильное меню, `.scrolled` на шапке и якоря — в `app.js`, 60 строк без зависимостей. В Next.js это переносится в клиентский компонент шапки.
